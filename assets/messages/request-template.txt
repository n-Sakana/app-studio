## 回答の形式

JSONオブジェクトを1つだけ返す。前後に説明を書いてもよいが、JSONは1つだけにする。

**key と action の値は、下に挙げた英語ASCIIの固定語だけを使う。**
対象アプリの表示名を原文のまま書いてよいのは title / notes / expect / why の中身だけ。

- 最上位の key は次だけ: format / version / title / notes / steps
  - format は "pui-plan"、version は 1（引用符を付けない数値）
- steps の各要素の key は次だけ: id / action / target / value / expect / why
  - id は整数（引用符を付けない）
- action に使えるのは次だけ: {actions}
- value が必要な action: {valueActions}
- 部品の指し方は次の2つだけ:
  - {"element": "E12"} — 調査資料の部品台帳にある Component ID。台帳に無い id は作らない。
  - {"point": {"x": 100, "y": 200}} — 画面座標。台帳に該当する行が無いときだけ使う。
- expect には「この操作で何が起きるはずか」を書く。実行後、実際に観測した変化と突き合わせる。
- why には「調査資料のどの情報からそう判断したか」を書く。

## このツール側の前提

- 既定は読取専用。read 以外を実行するには利用者が画面で明示的に許可する。
- 実行時に対象の点を別のwindowが覆っていたら、その操作は実行せず拒否する。
- password欄への setValue と keys は常に拒否する。
- 各操作の結果は success / failed / blocked / notSupported / unknown の5値で記録する。
  pattern を公開していても操作前後の変化を観測できなければ unknown であり、成功へ丸めない。
- 手順は上から順に実行する。1手順ごとに 0.5 秒待つ。
- 手順が1つでも形式に合わなければ、その手順だけ捨てるのではなく plan 全体を拒否する。
