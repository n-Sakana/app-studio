# App Studio 仕様

## 1. 目的

App Studio は、インストール権限の限られた Windows 端末へテキストファイルだけを持ち込み、既存アプリケーションを **AI に自動化させるための材料** に変えるツールである。画面を選んで意味構造を取得し、人が実際に行う操作を記録し、その記録を実アプリの上で再実行する。

本書が仕様の正本である。

## 2. 配布・起動構成

- 持ち込む実行形式はない。`launch.vbs` が Windows PowerShell 5.1 を非表示起動する。
- `app-studio.ps1` は `src/*.cs` を名前順で読み、.NET Framework の `Add-Type` でメモリ内コンパイルする。
- UI は WPF。選択オーバーレイ・録画枠・録画コントロールも WPF ウィンドウで、いずれも App Studio 自身として識別される。
- UIA 取得と UIA 操作は OS 標準の `powershell.exe` 子プロセスへ隔離する。active worker と warm spare を各1つ持ち、期限超過時は active を終了して spare へ切り替える。
- worker との IPC は UTF-8 JSON Lines の stdin/stdout であり、生の UIA 要素を process 境界へ渡さない。
- 外部通信、追加 Runtime、NuGet package、同梱 DLL は使わない。

## 3. 主役は3つ

### 3.0 画面は3つの形を持つ

起動直後は **小さなランチャ**（660 x 356）で、「スナップ」「録画」の2ボタン、［記録を見る］［設定］、そして状態1行だけを出す。**結果領域は持たない。** 設定はダイアログで開く。

スナップまたは録画が終わると **結果画面**（1120 x 840）へ移る。左にセッション一覧、右に取得結果・操作一覧・画面・限界・詳細設定を出す。topbar の［← 戻る］でランチャへ戻る。

結果画面の［コード編集］から **コード編集画面**（1120 x 840）へ進む。上に形式と状態と操作、中央にエディタ、下に AI との往復を置く。［← 戻る］はランチャではなく結果画面へ返す。**AI 相談はこの画面の中で完結し、独立した AI モード・可視化ペイン・高機能モードを作らない。**

大きな画面を最初から抱えないのは、起動直後に必要なのは「何を始めるか」だけであり、読むものがまだ無いからである。結果を読む段になって初めて、読むための大きさになる。

### 3.1 スナップ

1. ［スナップ］で App Studio 本体を隠す。
2. 画面全体を薄く暗転する全画面オーバーレイを出す（各ディスプレイに1枚）。
3. ポインタ下のトップレベルウィンドウを枠と1行のラベルで示す。クリックで決定、`Esc` または右クリックで中止。
4. 決定後にオーバーレイを閉じ、対象を前面へ出して取得する。
5. 取得と撮影が終わったら **App Studio を前面へ戻し、キーボードフォーカスも戻す。** 撮影のために対象を前面へ出すので、そのままでは操作者の手元が調査対象側に残る。結果を出したのに触れないのでは仕事が終わっていない。前面化に失敗した場合はその事実を画面に出す。

**ポインタ下のウィンドウは `WindowFromPoint` では求めない。** オーバーレイ自身がポインタ下にあるからである。`EnumWindows` が返す重なり順を前から辿り、点を含む最初の可視トップレベルウィンドウを採る。子ウィンドウ、cloaked window、透過レイヤードウィンドウ、App Studio 自身のプロセスは除外する。

取得する事実は 5 章のとおり。画像はオーバーレイを閉じたあとに撮るので、暗転も選択枠も本体も写らない。

### 3.2 録画

1. ［録画］で本体を隠し、3・2・1 のカウントダウンを出す（`Esc` で中止）。
2. 前面ウィンドウを控えめな枠で追従表示し、画面上端に「● 録画中 mm:ss ／ 停止」を出す。
3. **対象アプリを固定しない。** 前面ウィンドウが変わればそれ自体を1ステップとして記録し、その窓をその場で取得する。

**記録は2層で残る。** 生タイムライン (`input.jsonl`) は監視が見たイベントを起きた順に、間隔つきで全部残す ― 押下・解放・click・double click・drag・wheel、コマンドキーの down と up、打鍵が起きたという事実、前面ウィンドウの変化、キーボードフォーカスの移動。ステップ (`steps.jsonl`) はそれが何を意味したかを、座標ではなく要素で記述したもので、再生が実行するのはこちら。

**ポインタは OS の低レベル hook で見る。** wheel には読める状態が無く、drag の解放点も double click も「前回聞いてから押下があったか」だけを答える polling には存在しない。hook の callback は何が起きたかを待ち行列へ積むだけにする（callback が遅いと端末全体の入力が遅れるため）。hook を張れなかった場合は左ボタンの押下だけを見る縮退動作になり、**その事実と失われる情報をセッションの限界として明記する**。マウスの移動そのものは記録しない。

**キーボードは hook しない。** 固定監視リストのキー状態を1 tick に1回だけ読む。名前を書き留めるのはリスト上のコマンドキーだけで、通常の打鍵は「打鍵が起きた」という事実だけを取り、何が入力されたかは常に受け取った欄から読み戻す。1 tick に1回なのは、キー状態の読み取りが「前回聞いてから押されたか」のビットを消費するため、2箇所から読むと半分ずつ取りこぼすからである。

**録画開始時点で既にフォーカスがある欄を最初に確かめる。** 窓がカーソルの入った状態で開き、操作者がそのまま打ち始めるのは日常の入力であり、click を待っていると全部落ちる。フォーカスが動いたときも同じ手順で、離れた欄を書き出し、新しい欄を見張り直す。

**押下の監視と、押されたものの記述は別スレッドで行う。** 1回の記述には UI Automation の問い合わせと、ときには窓1つ分の取得が入り、数百ミリ秒かかる。一方 OS が答えられるのは「前回聞いてから押下があったか」だけで、何回あったかは答えない。したがって記述しながら監視すると、記述中の押下はまとめて1回に潰れて**記録から消える**。監視側は押下と座標を読むだけ（マイクロ秒）にして待ち行列へ積み、記述側が順に取り出す。読み手が1つなので順序は保たれる。待ち行列が上限に達した場合は、失われた件数を「取得できなかったこと」に明記する。
4. ［停止］または `F9` で終了し、出力を書き出す。

枠と停止コントロールは App Studio のウィンドウであり、
- 前面追跡の対象から除外され、
- ポインタ所有プロセス判定で自プロセスと分かるため押しても記録されず、
- キーフレーム撮影の直前に OS レベルで画面から消される（WPF の Hide だけでは1フレーム残るため `ShowWindow(SW_HIDE)` も出す）。

記録するステップの種類は `appSwitch` / `click` / `keyChord` / `textInput` / `secretInput` の5つ。各ステップは時刻・開始からの経過・アプリ・ウィンドウ（title / class）・前後の画面 ID・対象要素の識別情報・取得源・ロケータ一覧と確度・観測できた効果・診断・取得できなかった事項を持つ。

**生のマウス移動は記録しない。** 押下の遷移だけを見る。`GetAsyncKeyState` は「今押されているか」に加えて「前回呼び出し以降に押されたか」も見るため、polling 間隔より短い click も落とさない。

### 3.3 再生

記録した操作を実アプリの上で再実行する。動画再生ではない。

各ステップで、
1. 期待するウィンドウを **class と実行ファイル名** で探し、前面へ出す。前面化は結果を確認し、来なければ `failed` とする（要求を出したことを成功と呼ばない）。
2. そのウィンドウを取得し直し、記録したロケータで対象要素を解決する。
3. 解決できたら操作を実行し、試行列を記録する。

**解決できない・複数一致するときは止まる。** 記録時の座標へ落とすことはしない。理由は `ambiguous` / `not-found` / `no-locator` / `wrong-window` として画面と記録の両方に出る。

再生は実アプリを操作するため、明示的な許可を得るまで実行しない。［再生する］を許可なしで押した場合は、**何が起きるかを説明するダイアログを出してその場で許可を求める**。断られたら何も送らない。画面の隅に1行出すだけの拒否にはしない ― ボタンを押して何も起きないように見えるのは、拒否ではなく故障に見えるからである。

### 3.4 記録する事実

再現に要る文脈を step ごとに残す。

| 事実 | 内容 |
|---|---|
| 種別 | click / doubleClick / drag / wheel / keyChord / textInput / secretInput / appSwitch |
| ボタン | left / right / middle |
| 位置 | 物理ピクセル、drag は開始点と解放点、DPI と monitor |
| 間隔 | 直前の操作からの `gapMs`、押していた `holdMs` |
| 対象 | ウィンドウ、要素、ロケータ、取得層 |
| 解放先 | drag を離した要素とそのロケータ |
| キーボード | その瞬間フォーカスを持っていた要素とそのロケータ、modifier |
| 影響 | 直後に観測できたウィンドウ／タイトルの変化 |

## 4. プライバシー規則

この規則は一箇所（`Privacy`）にあり、他のどこにも判断を持たせない。

- **キーストリームを読む API は製品ソースに存在しない。** `WH_KEYBOARD` / `WH_KEYBOARD_LL` / `GetKeyboardState` / `ToUnicode` / `GetClipboardData` / `RegisterRawInputDevices` は無い。`SetWindowsHookEx` は **`WH_MOUSE_LL` の1種類にだけ** 使う ― wheel には読める状態が無く、drag の解放点も double click も polling には存在しないため。`test-privacy` が、ソース中の hook id が `WH_MOUSE_LL` だけであること、呼び出し箇所がすべてそれを渡していることを固定する。
- キーボードは hook しない。**固定の監視キー表** に対する `GetAsyncKeyState` だけで見る。表に無いキーは一度も問い合わせない。
  - Ctrl / Alt / Windows キーを押している間だけ、英数字キーを chord として記録する。
  - Enter・Tab・Esc・F1〜F12 は単独でも記録する。
  - **修飾なしの英数字・記号キーはキー名を記録しない。** それは文字であって命令ではない。
  - ただし英数字・Space・BackSpace・Delete は、**「打鍵が起きた」ことだけ**を知るために状態を読む。どのキーだったかは待ち行列にも記録にも渡さない。これが無いと、操作者が押した覚えのない欄（窓が開いた時点でカーソルがある欄）への入力に気づけない。この検出用の表は監視キー表の部分集合であり、`test-privacy` がその包含関係を固定する。
  - 句読点キーは監視表に入っていない。したがって**句読点だけで構成された入力は「打鍵が起きた」ことに気づけない**。その場合でも値は要素から読み戻すので内容は失われない（`test-ime-e2e` の句読点のみの欄で実測）。
- 入力した文字は **キー入力から取らない。** 押した先の要素を覚えておき、フォーカスが離れたときにその要素の値を読み戻して差分を記録する。ショートカットではフォーカスは離れないので、値を書き出したうえで監視を継続する。
- **秘密欄の値は保存しない。** 判定は `IsPassword`、`ES_PASSWORD` ウィンドウスタイル、名前 / AutomationId / HelpText の語（password, passwd, pin, secret, token, api key, cvv, one-time, otp, mfa code など）。該当した要素は値を読まず、`secretInput` として「値は記録していない」ことを明記し、再生時は操作者に入力を求めて止まる。
- **画像でも秘密欄の矩形を黒塗りする。** スナップの撮影でも録画のキーフレームでも同じ。黒塗りの有無と件数は画面ごとの note に書く。
- クリップボードは読まない。前面でないアプリの内容は取らない。画面録画はしない。
- 値の記録方針はセッション単位で `recordText`（既定、再生に必要）と `lengthOnly`（文字数のみ、再生時に毎回入力を求める）を選べる。どちらであるかは `session.md` と `report.html` の両方に文章で書く。

## 5. 取得層と取得する事実

取得経路は UIA(raw view walk) → MSAA(`AccessibleChildren` walk) → Win32 child window 列挙 → 座標 grid hit-test。hit-test は前3者が薄いときだけ動く。**pattern は可否 property を読むだけで実行しない。**

要素ごとに、画面 (`screenId`) と `componentId`(`E<n>`)、取得元 (`sources`)、process、top-level HWND、HWND（無い場合は `hasHwnd:false`）、class/realClass、control type（および localizedControlType、MSAA role）、name、AutomationId、`RuntimeId`、矩形、visible/enabled/offscreen/keyboardFocusable/isPassword、対応 pattern、親子 path、frame 部品かどうか、ctrlId、style/exStyle を残す。値本文は取得しない。

provider ごとに state / 件数 / 所要 / 打切り理由 (`SCAN-MAXNODES` `SCAN-TIMEOUT` `SCAN-MAXDEPTH` `UIA-EMPTYTREE` `MSAA-NOELEMENT` `HITTEST-GRID` など) を必ず残す。

**どの画面も中身を1つも公開しなかった場合**、`report.html` と `session.md` は「このアプリは構造を公開していない。画像が唯一の記述であり、座標に基づく自動化はウィンドウが動けば壊れる」と明記する。要素表が1行あることを「1個の部品しかない窓」と読み違えさせない。

取得できなかった事項の一覧のあとには、それが空でも空でなくても **「これは完全性の証明ではない」** を必ず出す。

### Win32

`WindowFromPoint`、class/real class、`GetDlgCtrlID`、style/exStyle、物理矩形、親、z順、PID/TID、monitorId、DPI を取得する。caption は `SendMessageTimeout(SMTO_ABORTIFHUNG)` 150ms で読み、応答しなければ `partial / WIN32-HUNG` とする。UIA が失敗しても Win32 結果は残る。

### UI Automation

基本 properties、supported patterns、tree path、最大50 children を取得する。Custom/Pane/Window が子を一つも公開しない場合は `partial / UIA-EMPTYTREE` とする。期限超過時は worker を終了し、`unavailable / UIA-TIMEOUT` と `ACQ-RESTART` を残す。

### 画像

`BitBlt`、黒画像なら `PrintWindow(PW_RENDERFULLCONTENT)` を試す。秘密欄の矩形は黒塗りする。撮影の直前に対象を前面へ出し、App Studio 自身のウィンドウは全て画面から消す。

## 6. ロケータ

実際に取得できた材料だけから候補を作る。**HWND、UIA RuntimeId、値本文はロケータに入れない。**

| strategy | 材料 | 再生で使うか |
|---|---|---|
| `uia.automationId` | AutomationId（数字だけでないもの）+ ControlType | 使う |
| `uia.nameControlType` | Name + ControlType | 使う |
| `uia.treePath` | 階層 path | 使う |
| `win32.ctrlId` | 0/-1 でない ctrlId + 安定化した class | 使う |
| `win32.classIndex` | 同一 class 中の順番 | **使わない** |
| `window.relative` | ウィンドウ内の相対位置 | **使わない** |

下2つは記録し、レポートと `session.md` に載せる（自動化を書く人には有用な材料である）が、**「どれを操作するか」を決めることには使わない**。位置も兄弟中の順番も、それが何であるかを言っていないからである。レイアウトが変わったときに「その class の1番目」を叩くのは、答えの形をした推測になる。

確度は材料の質から決める。AutomationId は high、名前が窓内で一意なら high・重複していれば medium、階層 path と ctrlId は medium、位置と順番は常に low。

解決結果は `resolved` / `ambiguous` / `not-found` / `no-locator` / `no-elements` のいずれかで、どの strategy を何件で試したかの trace を必ず残す。

## 7. 実行経路と試行列

取得と再生の経路を混同しない。

- 取得: UI Automation / MSAA / Win32 / coordinate hit-test
- 再生: UIA patterns / Win32 messages / SendInput

**MSAA は取得専用である。** 操作の実行には使わないので、経路の選択肢にも出さない。

既定は `auto`：UIA pattern → Win32 message → SendInput。詳細設定で `UIA のみ` / `Win32 のみ` / `SendInput のみ` に **狭める** ことはできるが、広げることはできない。

各アクションについて試行列を保存する。例:

```
uia.InvokePattern:notSupported -> win32.BM_CLICK:success
```

各試行は経路・method・結果・所要 ms・error code / message・観測できた前後の変化を持つ。ガードで止まった場合も `guard` 経路の1試行として「何も送っていない」ことを残すので、試行列に穴は空かない。

**経路の繰り上がりは、前の経路が `notSupported`（＝何もしていない）を返した場合と、`focus` が失敗した場合だけである。** 状態を変える操作を、方式の比較のために複数経路で連続実行することはしない。明示的な reset / undo なしの破壊的比較を禁じる。

結果は `success / failed / blocked / notSupported / unknown` の5値。pattern を公開していても前後変化を観測できなければ `unknown` であり、`success` へ丸めない。同一要素・同一 kind は1秒間隔に制限する。

安全ガード（読取専用の既定、覆われた点の拒否、素性不明時の書込み拒否、password への `setValue`/`keys` 拒否）は再生でも同一である。

## 7.5 再生の順序・間隔・フォーカス

- **順序**は記録順。1つでも `done` 以外になったらそこで止め、理由を残す。
- **間隔**は記録された `gapMs` をそのまま待つ。ただし下限 120 ms・上限 4000 ms で挟む。下限が無いと直前の操作を描き終える前に次を送ることになり、上限が無いと休憩時間まで再生することになる。待った実測値を step に書く。
- **待ち**は必ず有界。操作のあとは前面ウィンドウとタイトルが動かなくなるまで、最大 2500 ms 待つ（ダイアログの立ち上がりも遅い描画もここで吸収する）。到達したかどうかではなく、待った実測値を事実として残す。
- **フォーカス復帰**：キー送出の前に、記録時にキーボードを持っていた要素を解決して復帰させる。記録がそれを持たない場合はその旨を試行列に書いて続行する。持っているのに復帰できない場合は `focus-not-restored` で止め、**何も送らない**。
- double click / drag / wheel には UI Automation の pattern も window message も存在しないため、経路は SendInput だけになる。試行列にはその旨（`UIA-NOPATTERN` / `WIN32-NOROUTE`）を明記し、試したふりをしない。
- 同一要素への連続操作を1秒に1回へ制限する対話用の rate limit は、再生には適用しない。操作者が1秒に2回押したのは押すつもりだったからである。

## 8. 保存構造と出力

### 8.1 セッション（内部正本）

`runtime/sessions/<sessionId>/` が1セッション1フォルダ。**明示的な保存操作はない。**

| file | 内容 |
|---|---|
| `meta.json` | 索引。schema (`app-studio/session/2`)・種別・時刻・題名・値方針・アプリ一覧・件数・限界・省略 |
| `elements.jsonl` | 要素1件1行 |
| `screens.jsonl` | 画面1件1行。画像の path と hash、撮れなかった理由、黒塗り件数 |
| `input.jsonl` | 生の入力タイムライン。イベント1件1行、直前からの間隔つき。監視が見たものを全部残す |
| `steps.jsonl` | 操作1件1行。発生時に1行、効果を観測してからもう1行。**読み手は同じ stepId の最後の行を採る** |
| `replay.jsonl` | 再生1ステップ1行。試行列を含む |
| `shots/*.png` | 画像原本（黒塗り済み、無劣化 PNG） |
| `out/report.html` | 人が読むレポート |
| `out/ai/session.md` | AI へ渡す1つめ |
| `out/ai/screens.pdf` | AI へ渡す2つめ |

書けない場合は画面に理由を出し、記録件数を0のまま進めない。

### 8.1.1 情報設計（画面と report.html に共通）

読み手が最初に要るのは「何が起きたか」「どれだけ欠けたか」「次に何をするか」の3つだけである。したがって画面も HTML も次の順で並べる。

1. **結論** ― 状態（成功／一部失敗／失敗／記録なし）と1文。主語と結果を省かない。
2. **数値** ― 操作・画面・要素・取得できなかったものの件数。
3. **警告** ― 欠落があるなら件数と影響だけ。全文は詳細側。
4. **次の一手** ― 1つだけ。
5. **詳細** ― 上記の根拠すべて。

**折り畳みは1段だけとする。** 折り畳んだ先にさらに折り畳みを置かない。開いた先は平らな一覧を持つ1つのスクロール箱にする。開いた読み手が見つけるべきものは答えであって、次に開くものではない。

状態語・件数の言い回し・「次の一手」は1箇所（`SessionVerdict`）で決め、画面・`report.html`・`session.md` が同じ語を使う。3つの出力が同じセッションについて違う答えを出してはならない。

### 8.2 report.html

自己完結。外部参照を一切持たず、画像は data URI で内包する。**GUI の見た目を再現しない。** 再現しても読者が知らないことは増えないからである。

- 上部固定の絞込み欄。入力すると要素行・ステップ・画面行が絞られ、該当した折畳みは開く。
- 画面（PDF ページ番号との対応つき）／操作時系列／要素表／再生結果／取得層と限界。
- 要素表の列: id・screen・取得源・control type・name・AutomationId・class・ctrlId・矩形・状態・patterns・階層 path。
- 埋め込む画像は長辺 1100px・品質78へ縮小し、**縮小したことと原本の場所をその場に書く**。総量に上限があり、超えたら埋め込まずに理由を書く。
- light / dark は読み手の設定に従う。

### 8.3 AI 向け出力は常に2ファイル

`out/ai/` に入るのは `session.md` と `screens.pdf` の **ちょうど2ファイル**である。JSON も画像別添も増やさない。「`ai/` の中身を渡す」が完全な指示として成立する。

`session.md` は次の9節を持つ。

1. 端末・画面・座標系（**物理ピクセルであること、スケール係数を掛けてはいけないこと**を明記）
2. 何を記録し何を記録しなかったか（プライバシー規則の文章化）
3. アプリケーション（プロセス ID は当時の値であり後の実行では無意味だと明記）
4. 画面（PDF ページ番号、画像の有無と無い理由）
5. 要素
6. 操作の時系列（ロケータ一覧、確度、取得できなかった事項）
7. 再生結果（試行列を含む）
8. 取得層と限界
9. ここから自動化を書く人への注意

**画像の base64 は入れない。** 表のセルに現れる `|` と改行は無害化する（列が壊れると内容が読めなくなるため）。

`screens.pdf` は1画面1ページ。ページ冒頭に Screen ID・`page N of M`・セッション ID・ウィンドウ名・class・寸法・部品数・撮影時刻・そのページに関係するステップ ID・note を書く。同梱 font を持たないため caption は ASCII のみで、非 ASCII は `?` になる旨をページ自身に書く（原文は `session.md` にある）。

### 8.4 容量予算

`screens.pdf` には明示的な予算がある（既定 6144 KB、詳細設定で変更可）。

超えている間、次の順で試す: 1800px 無劣化 → 1600px 品質85 → 1400px 品質78 → 1100px 品質70 → 900px 品質60。

**縮小段が前より大きなファイルを作った場合は、それを採らずに最小のものへ戻す。** ウィンドウのスクリーンショットは平坦な色が多く、無劣化のほうが小さいことが普通にある。そこで劣化させたうえに画面まで落とすのは、何も買わない損失である。この事実も文章として出力に書く。

縮小を尽くしても収まらないときだけ画面を落とす。落とすのは、どのステップも参照していない中間の画面から。**落とした画面 ID と理由は `session.md` と `report.html` の両方に書く。** 1ページまで削っても収まらない場合は、そのまま書き出したうえで「予算を満たせなかった」と書く。

## 8.5 コードとしての録画

録画は `runtime/sessions/<id>/code/` に **PowerShell と VBA の両方**として書き出される。両者は同格であり、片方を既定にしたり書き出し扱いにしたりしない。生成は `36_ScriptModel` が作る単一の操作列からのみ行われるので、2つの言語が同じ録画について食い違うことがない。

両言語が持つ操作はこの9つで、名前も意味も同じである。

| 操作 | 意味 |
|---|---|
| `FindWindow` | 記録したクラスと題名に一致する窓が**ちょうど1つ**になるまで待ち、前面へ出す。複数一致は停止する |
| `FocusElement` | 記録時にキーボードを持っていた要素へフォーカスを戻す |
| `InvokeElement` | 要素を押す。要素が公開するパターンを優先し、合成入力は次善で前面を要求する |
| `SetElementText` | 要素へ文字を書く。パスワード要素へは常に拒否する |
| `ReadElementText` | 効果の確認のために要素を読み戻す |
| `SendKeys` | 記録したショートカットを1つ送る。フォーカスを戻した後にのみ送る |
| `WaitGap` | 記録された操作間隔を待つ（下限 120 ms・上限 4 秒） |
| `WaitIdle` | 前面が変化しなくなるまで、明示した上限まで待つ |
| `AskSecret` | 記録が意図的に持たない値を操作者へ求める。どこにも書き残さない |

**覚えた座標を押してはならない。** 要素はロケータの順で解決し、要素内の位置は「現在の要素矩形に対する割合」で表す。`window.relative` は記述であって住所ではないので、生成コードには一切書かれない。住所を持たない step は黙って落とさず `Unsupported` として理由付きで停止する。

VBA は UI Automation を前提にできないため、住所は `win32.ctrlId`（クラス名＋コントロール ID）と `win32.classIndex`（クラス名＋順番）の2つに限られる。UIA でしか届かない step は、その旨をコード中に書いて停止する。**座標で代用しない。** 秘密の step で VBA は値を受け取らない。フォーカスを合わせて操作者が直接入力するのを待つので、値がプロジェクトに存在しない。

検証は言語ごとに実際に可能なことだけを行う。PowerShell は Windows PowerShell 5.1 自身の parser に読ませる。VBA は**構造検査のみ**であり、結果には常に「これはコンパイルではない」と書く。実行は PowerShell が別プロセス、VBA は VBA ホスト（Excel）が必要で、ホストが無い場合・VBA プロジェクトへのアクセスが信頼されていない場合は**その事実を名指しで報告する**。代替で済ませて合格にしない。

## 8.6 AI との往復

送りは原則**1クリック・1コピー**。テキスト1個に、依頼内容・返却形式・操作API仕様・端末と座標系・操作ログ（間隔とフォーカスを含む）・window/element 台帳・取得できなかったもの・現在のコードの8節を入れる。これが1回のペーストに収まらない長さのときだけ、行境界で番号付きに分割し、各部に `REQUEST nn OF nn` を付ける。**収めるために内容を削らない。** 依頼テキストは `runtime/sessions/<id>/code/request.md` に書き、`ai/` へは入れない（8.3 の2ファイル規則を保つため）。添付は利用者から見て常にテキスト1個と PDF 1個である。

受けは原則**1ペースト**。返答は `#@APPSTUDIO <request id> ...` の区切り行で包まれる。

```
#@APPSTUDIO <request id> SUMMARY BEGIN / SUMMARY END
#@APPSTUDIO <request id> BEGIN <powershell|vba> <name> ... END ...
#@APPSTUDIO <request id> COMPLETE <件数>
#@APPSTUDIO <request id> PART nn OF nn          （1ファイルずつ返す場合）
#@APPSTUDIO <request id> NOCHANGE UNNECESSARY|IMPOSSIBLE|UNCLEAR
```

**request id が一致しない返答は取り込まない。** 古い返答や別の依頼への返答が誤って適用されることがないようにするためで、これは利便性ではなく安全性の要件である。1回の貼り付けから複数の PowerShell ファイル・VBA モジュールを識別して仕分ける。分割返答は欠落・順序・重複・総数不一致・同番号での内容衝突を検査して再結合する。

不正形は20種を区別し、**すべてに操作者が次に何をすればよいかを書いた日本語の文**を持つ（`assets/messages/intake-*.txt`）。空・区切り行なし・別依頼・途中切れ・件数不一致・重複・未知の言語・不正な名前・空ファイル・分割各種・変更なしの検証3種・質問返し。**質問は返答として認めない。** 判断できない場合は `NOCHANGE UNCLEAR` と理由で返させる。

チャットクライアントが付けた装飾（引用記号・箇条書き・HTML タグ・実体参照・全角の記号・バッククォート）は剥がす。ただし**剥がすのは、元は区切り行でなかった行が区切り行になる場合だけ**であり、ファイル本文は逐語で扱う。この処理は区切り行を作り出すことがなく、除去しかしない。

**取り込みは即時上書きしない。** 差分を示し、［反映］で初めて置き換える。録画から生成した初期版と、反映直前の版の両方へ戻せる。取り込めなかったときは理由を出す。黙って一部だけ適用したり、失敗を成功に見せたりしない。

## 9. ホットキー

| 操作 | 既定 |
|---|---|
| 録画・再生の停止 | F9 |
| 緊急停止 | Shift+F12 |

登録済みの組合せと衝突した場合は `HOTKEY-TAKEN` を診断へ出し、Shift または Ctrl を足した代替を試す。実際の割当は `runtime/settings/hotkeys.txt` に保存する。設定を書けない場合も画面のボタンで継続できる。緊急停止は録画と再生を止め、実アプリ操作の許可を解除する。

## 10. 既知の限界

- 名前も AutomationId も階層 path も ctrlId も持たない要素は再生できない。位置と兄弟中の順番は記録して見せるが、住所としては使わない。
- 対象が構造を公開しない場合、取得はウィンドウ単位まで落ちる。この事実は隠さず、画像が唯一の記述であることを明記する。
- 録画中にウィンドウを跨ぐと、その窓の取得に数秒かかる。その間の操作は取得の完了後にまとめて処理されるため、記録の順序は保たれるが時刻には取得時間分の遅れが乗る。
- 録画開始時点で既にフォーカスがある入力欄への入力は、開始時と焦点移動時にフォーカス先を確かめて監視を始めるので拾える。ただし窓が1つで内部を自前描画するアプリでは `hwndFocus` が動かないため、その窓の内部での焦点移動は観測できない。
- 全景画像は自動 mask できない。
- Java AWT/Swing、SAP GUI、製品固有 API は検出後に別経路が必要である。
- `SysListView32 / SysTreeView32` の行 data は取得せず `NEEDS-B3` を出す。
- OCR は対象外である。低 level 入力 hook は **pointer にだけ** 使う（`WH_MOUSE_LL`）。keyboard は hook しない。hook を張れない環境では左 button の押下だけを見る縮退動作になり、その事実と失われる情報を session の限界に明記する。
- 画像、UIA、`PrintWindow`、`SendInput` の品質は対象実装・権限・desktop 状態に依存する。
- 高 DPI・複数画面の構成では物理矩形の一致を確認すること。RDP と対象現場の DPI 混在は現地確認事項である。
