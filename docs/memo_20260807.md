# App Studio 改修方針まとめ

## 1. 目標

App Studio の目標を次の形にする。

```text
実操作を録画する
↓
録画中に画面・子コントロール・操作イベントを取得する
↓
録画後に操作モデルへ整理する
↓
録画操作をWin32中心の操作レシピとして再現する
↓
同じ情報をAIチャットに渡して派生操作を生成できるようにする
```

既存の実稼働VBAでは、対象アプリ操作に以下が使われている。

```text
EnumWindows
FindWindow
EnumChildWindows
SetForegroundWindow
SendMessage
PostMessage
WM_SETTEXT
WM_GETTEXT
BM_CLICK
CB_GETCOUNT
CB_GETLBTEXT
CB_SETCURSEL
```

この操作作法を App Studio の生成対象に含める。

---

## 2. 取得タイミング

### 2.1 録画中に取得するもの

複数画面遷移を扱うため、画面が表示されている間に必要情報を取得する。

```text
screenId
title
class
hwnd at record time
rect
visible / enabled
foreground state
child hwnd list
child class
child text
child visible / enabled
click target
key action
before screen
after screen
```

録画ログは、前面画面、入力イベント、画面遷移、操作ステップを結び付けて保持する。

### 2.2 録画後に行うもの

録画後に行うのは取得ではなく、録画中に取得した情報の整理・解析・コード化である。

```text
画面台帳の整理
子コントロール台帳の整理
操作ログとの対応付け
操作可能性の推定・実測結果の整理
トップレベルウィンドウクリックの分類
Win32操作レシピ化
AIチャット用資料化
コード生成
```

## 3. 複数画面遷移の扱い

画面遷移は、Screen ID、Step、Transition を結び付けて管理する。

```text
Screen:
  screenId
  titleCondition
  classCondition
  hwndAtRecordTime
  childSnapshotId

Step:
  stepId
  beforeScreenId
  afterScreenId
  actionType
  targetWindow
  targetControlCandidate
  observedEffect

Transition:
  fromScreenId
  toScreenId
  causedByStepId
  expectedWaitCondition
```

記録中に各画面の情報を取り、録画後に画面遷移グラフとして整理する。

## 4. 対象アプリ風 fixture を作る

本物の対象アプリに依存せず、App Studio の失敗を再現するための WinForms fixture を作る。

fixture に含めるもの。

```text
検索画面
処理中画面
一覧画面
詳細画面
画像画面
入力欄
ボタン
コンボボックス
タブ
戻るボタン
グリッド風領域
大量の子コントロール
UIAで不安定に見える領域
Win32では操作できる子コントロール
```

---

## 5. A3型失敗を fixture で再現する

最初に再現する失敗は、一覧画面クリックが `element.not-found` で停止するケース。

```text
記録:
  一覧画面へのクリック

再生:
  UIA locator が一致しない
  target element が解決できない
  element.not-found
  実アプリへ操作を送信しない
```

fixture では、一覧画面内に具体的な Button/Edit ではないグリッド風領域を置き、トップレベルウィンドウまたは Pane 相当へのクリックとして記録される状態を作る。

---

## 6. トップレベルウィンドウクリックの扱い

トップレベルウィンドウへのクリックは、操作分類で `ActivateWindow` に変換する。

```text
Recorded:
  click on top-level window

Recipe:
  FindWindow / EnumWindows
  SetForegroundWindow
  WaitIdle
  Confirm foreground
```

期待する変換は以下。

```text
Before:
  A3 = ClickElement
  ↓
  UIA locator not-found
  ↓
  stop

After:
  A3 = ActivateWindow
  ↓
  FindWindow / EnumWindows
  ↓
  SetForegroundWindow
  ↓
  success
```

## 8. MSAA取得オプション

MSAAは取得専用として扱い、録画中の負荷を制御できるようにする。

```text
MSAA Off
MSAA Shallow
MSAA Actionable only
MSAA Full
```

用途は以下。

```text
MSAA Off:
  録画中の軽量化を優先する。

MSAA Shallow:
  クリック地点周辺、フォーカス周辺のみ取得する。

MSAA Actionable only:
  visible / enabled / focusable かつ操作候補だけ取得する。

MSAA Full:
  解析・調査用に使う。
```

### 10.3 ComboBox


## 11. 録画操作を操作レシピへ変換する

録画された人間操作を、Win32中心の操作レシピに変換する。

### 11.1 入力欄

```text
1. 対象画面を探す
2. 子コントロールを列挙する
3. 対象入力欄を解決する
4. WM_SETTEXTを送る
5. WM_GETTEXTで読む
6. 期待値と比較する
7. 不一致時に再送する
```

### 11.2 ボタン

```text
1. 対象画面を探す
2. 子コントロールを列挙する
3. 対象ボタンを解決する
4. BM_CLICKを送る
5. 期待画面または値変化を待つ
```

### 11.3 コンボボックス

```text
1. 対象画面を探す
2. 子コントロールを列挙する
3. CB_GETCOUNTで候補数を取る
4. CB_GETLBTEXTで候補を読む
5. 目的値のindexを探す
6. CB_SETCURSELで選択する
7. 選択結果を確認する
```

### 11.4 トップレベルウィンドウ

```text
1. 対象画面を探す
2. SetForegroundWindowを送る
3. 前面化を確認する
```

## 12. 失敗時処理

既存VBAの作法に合わせて、確認・再試行・停止をレシピ化する。

```text
入力不一致:
  再送
  再取得
  回数上限で停止

画面遷移待ち:
  期待画面を探索
  処理中画面を許容
  timeoutで停止

予期しない画面:
  メッセージ画面確認
  戻る操作候補
  理由付き停止

停止要求:
  Stop flag確認
  安全に中断
```

## 13. AIチャット生成用パッケージ

録画した操作以外の派生操作をAIチャットで生成するために、次の資料を出す。

```text
operation-model.md
screen-catalog.md
control-catalog.md
operation-capability.md
recorded-recipes.md
successful-patterns.md
unsupported-patterns.md
fixture-notes.md
```

AIチャットへ渡す資料には、画面・子コントロール・操作方式・成功確認・失敗時処理を含める。

### 優先度1

```text

```

### 優先度2

```text
トップレベルウィンドウクリックを ActivateWindow に分類する
```

```text

```

### 優先度4

```text

```

### 優先度5

```text

```

### 優先度6

```text

```

### 優先度7

```text

```

## 15. 最終方針

```text
対象アプリ風fixtureを作り、今回のA3型失敗を再現する。

録画中に、画面遷移ごとのWin32情報と操作イベントを取得する。

録画後に、取得済み情報を画面台帳・子コントロール台帳・操作可能性台帳へ整理する。

トップレベルウィンドウクリックをActivateWindowへ分類する。

録画操作を、FindWindow / EnumChildWindows / WM_SETTEXT / WM_GETTEXT / BM_CLICK / CB_* を使う操作レシピへ変換する。

その操作レシピと台帳をAIチャットへ渡し、録画していない派生操作も同じ作法で生成できるようにする。
```
