# App Studio

Windows のアプリケーションを **AI に自動化させるための材料** に変えるツールです。画面を選んで中身を丸ごと取得し、人が実際に行う操作を記録し、その記録を実アプリの上でもう一度実行します。

実行形式 (EXE/DLL) を一切持ち込まず、インストールもレジストリ変更も行いません。`src/*.cs` を Windows PowerShell 5.1 の `Add-Type` でメモリ内コンパイルして起動します。インストール権限が無い端末や、持ち込み物が制限される現場を想定しています。

## できることは4つです

### スナップ

［スナップ］を押すと本体が隠れ、画面が薄く暗転します。ポインタを動かすと、その下のトップレベルウィンドウが枠で示されます。クリックで決定、`Esc` で中止。

決定したウィンドウについて、AI が自動化を書くのに必要な意味構造をできるだけ完全に取得します。UI Automation・MSAA・Win32 ウィンドウ列挙・座標ヒットテストの4経路を併用し、control type / name / AutomationId / RuntimeId / 矩形 / 状態 / 対応パターン / 階層 path / ctrlId / style と、取得元・打切り理由を1件1行で残します。ウィンドウの画像も撮ります。**選択オーバーレイも本体も画像には写りません。**

### 録画

［録画］を押すと本体が隠れ、3・2・1 のカウントダウンのあとに始まります。**特定のアプリに固定しません。** 前面アプリを横断して、実際の操作と画面遷移を記録します。

録画中は前面ウィンドウを控えめな枠で追い、画面上端に小さな「● 録画中 mm:ss ／ 停止」が出ます。この枠と停止コントロールは App Studio 自身として扱われ、記録対象からも操作対象からも外れ、キーフレーム撮影の瞬間には画面から消えます。

記録は2層です。**生のタイムライン**には、監視が見たものを起きた順に間隔つきで残します ― 押下と解放、click、double click、drag、wheel、コマンドキーの down と up、打鍵が起きたという事実、前面ウィンドウの変化、キーボードフォーカスの移動。**操作の一覧**には、それが何を意味したかを座標ではなく要素で残します。再生が実行するのは後者です。

録画を始めた時点ですでにカーソルが入っている欄への入力も拾います。マウスの移動そのものは記録しません。

**「録画中、ポインタの下にあるものを表示する」** を入れると、ポインタの下のコンポーネントを青い枠で囲み、その正体を近くに小さく出します。チップの1行目は**ウィンドウかコントロールか、そして題名** ― 目で見分けるのに要るのはこれだけです。クラス名・コントロール ID・プロセス・寸法は畳んであり、パネルの［詳細］で開きます。閉じている間も「開ける」ことがチップに書いてあります。

**枠はクリックを貫通する**ので押したいものを邪魔しません。App Studio 自身の窓なので**画像にも記録にも入りません**。既定は切で、**入口は3か所とも同じ設定です** ― ランチャの［録画］の下、録画中のパネル、詳細設定。どれで変えても同じ1つの値が変わります。

### 再生

動画の再生ではありません。記録した操作を **実アプリの上でもう一度実行** します。実アプリを操作するので、押したときに何が起きるかを説明したうえで許可を求めます。

各ステップで期待するウィンドウが前面にあることを確かめ、対象要素を意味的ロケータで解決します。キーを送る前には、記録時にキーボードを持っていた要素へフォーカスを戻します。曖昧・不一致・フォーカスを戻せない、のいずれでも黙って座標を叩かず、理由を出して止まります。

記録された操作間隔もそのまま待ちます（下限 120 ms・上限 4 秒）。操作のあとは画面が動かなくなるまで最大 2.5 秒待ち、待った実測値を残します。

### コード編集

セッションを選べば、中央のペインには **録画がそのまま動くコードになった状態** が入っています。開くための操作はありません。**C# と VBA は同格です。** 同じ一覧に同じ形で並び、どちらかを既定にしたり書き出し扱いにしたりしません。

編集はモジュールで、**手渡しは1ファイルで**行います。［ビルド］を押すと C# 側は `Workflow.cmd`、VBA 側は `Workflow.xlsm` が1本だけ作られます。できたものは隣の［生成物を起動］で、**渡された人と同じやり方で**その場から起動できます。「ビルドできました」という表示は、できたものが動く証拠ではないからです。置き場所は上部バーのフォルダアイコン（セッションのフォルダ）から開きます。`Workflow.cmd` は**それ単体で動きます** ― 何もインストールせず、隣に何も展開せず、ダブルクリックで走ります。中身は batch と PowerShell と C# が同居した1ファイルで、PowerShell が担うのはアセンブリを名指してコンパイルし呼ぶところまでです。**PowerShell を手書きさせません。**

`Workflow.xlsm` の作成に **Excel は要りません。** マクロ有効ブックは zip で、VBA プロジェクトはその中の1つの部品です。App Studio は有効な最小の**種ブック**を同梱していて、ビルドはその部品を「5モジュールを加えたもの」へバイナリで組み直します。したがって **「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」設定も要りません** ― この設定はプログラムがブックへマクロを書き込むのを止めるためのもので、以前のビルドはまさにそれをしていました。Office の無い端末でも同じブックができます。作れない事情（種ブックが無い・壊れている、VBA が受け付けないモジュール名、プロジェクトの文字コードで表せない文字）は**名指しで報告して何も作りません**。黙って直したブックは、画面と違うものを配ることになるからです。

**単一の巨大ファイルにはしません。** どちらの言語も同じ5つのモジュールに分かれます。

| module | 中身 | 編集するか |
|---|---|---|
| `Workflow` | 録画した操作列。**1行が1ステップ** | **ここです** |
| `RecordedFacts` | 録画が得た住所・間隔・入力値 | 狙う先を変えるときだけ |
| `RuntimeCore` | 9つの操作、待機、停止 | しません |
| `RuntimeLocator` | 記録した住所を「いまの要素」へ解決 | しません |
| `RuntimeNative` | 宣言とポインタ | しません |

`Workflow` の1行は操作名とステップ id だけです。待ち時間もキーボードの復帰も、その行に属して実行基盤が行います。**「1〜9を順に押す録画から5だけ外す」は、`Workflow` の5行目を消すだけです。** 数百行の実行基盤を探す必要はなく、他の4モジュールは1文字も変わりません。

左のモジュール一覧の上端には **PowerShell / VBA の切替**があります。2つは同じ録画の2通りの書き方なので、別画面へ行くタブではなく、同じ場所の**2位置のコントロール**です。押すと下の一覧が入れ替わるだけで、居場所は変わりません。

一覧は**渡す1本を頂点とした階層**です。PowerShell 側は `Workflow.cmd（渡す1本）` の下に「C#（主な編集対象）」の5モジュールと「PowerShell ラッパー（ビルド時に生成）」が並びます ― ラッパーは C# を読み込んで呼ぶだけの薄い層で、ビルドのたびに書き直されるので**読めますが編集はできません**。C# と並べて平置きすると、編集しない層が編集する層と同格に見えるので、**両方が属する1本の下**に置いています。VBA 側は `Workflow.xlsm（渡す1本）` の下に同じ5モジュールが並びます。**ビルドに入るものは全部出ます。**

エディタは行番号・等幅・色分け・検索を持ち、**長い行は既定で折り返します**（生成された1行はウィンドウより長いことが普通で、右端の先を読むために横スクロールが要るなら、それは読まれない行です）。中央ペイン右上の全画面アイコンは、左右のペインだけでなく**上部バーと下の状態行も畳んで、窓をエディターだけにします**（OS のフルスクリーンではありません）。同じ場所のアイコン、または `Escape` で戻ります。行き来しても編集中の内容・選択モジュール・カーソル・スクロールは失われません。

両方が同じ9つの操作を持ちます — `FindWindow` / `FocusElement` / `InvokeElement` / `SetElementText` / `ReadElementText` / `SendKeys` / `WaitGap` / `WaitIdle` / `AskSecret`。名前も意味も同じで、録画を操作列へ落とす場所が1つしかないので、2つの言語が同じ録画について食い違いません。

**覚えた座標は決して押しません。** 要素は録画が作ったロケータの順で見つけ直し、要素の中のどこかは「いまの要素矩形に対する割合」で表します。住所を持たない step は黙って落とさず、理由を出してそこで止まります。

`FindWindow` は録画が知っていること全部 ― **クラス名・題名・アプリケーション** ― で絞ります。**押せないウィンドウは候補ではありません**（不可視、デスクトップが隠している cloaked、大きさが無い、子ウィンドウ、貫通する重ね描き）。同じアプリの窓が2つ開いているなど、それでも複数が残る場合は「この録画が前面に持っていた窓」という step 本来の意味どおり**前面のものを使い、いくつ一致してどれを採ったかを実行時に出力し**、以後の step はその窓に固定します。黙って選びません。VBA は UI Automation を持たないので Win32（クラス名＋コントロールID、クラス名＋順番）で届く範囲だけを書き、届かない step はその旨をコード中に書いて停止します。座標で代用しません。

編集・検証・実行ができます。PowerShell は Windows PowerShell 5.1 自身に構文を見せ、実行も別プロセスで行います。VBA は構造検査までで、これは**コンパイルではない**と結果に必ず書きます。

VBA の**実行**には VBA ホストが要ります。［実行］はまずビルドと同じ手順で `Workflow.xlsm` を作り、それを Excel に開かせて `RunRecordedProcedure` を呼びます。**取り込みは行いません。** したがって実行にも VBA プロジェクトへのアクセスの信頼は要らず、必要なのは Excel があることだけです。ホストが無い場合、応答が返らない場合は、**どちらであるかを名指しで報告します**。黙って何もしなかったことにはしません。起動したホストは必ず閉じます。マクロそのものを禁じている端末では走りませんが、それは端末のマクロ実行ポリシーであって、ビルドの条件とは別のものです。

### AI との往復

右ペインの「AIに相談」タブの中で完結します。独立した AI モードも、可視化ペインも、高機能モードもありません。

依頼内容の欄は**空で開きます。** 何を頼みたいかを決めるのは利用者であって、アプリではありません（以前は「録画したアプリに対して確実に動くようにしてください」と最初から書かれていて、誰も書いていない依頼がそのまま送られる形でした）。空のあいだは「ここにAIへの指示を入力」と薄く出ますが、これは**枠の後ろに描いた案内**で、入力された文字ではありません。

**何を渡すかは、あなたが項目ごとに選びます。** 依頼内容の欄の下に「AIへ渡すもの」の一覧があり、14項目がそれぞれ独立したチェックです ― 端末・画面・座標系、記録範囲とプライバシー方針、対象アプリ、画面台帳、UI要素台帳、記録した操作、再生結果、カバレッジ・制限・診断、自動化ガイダンスと安全ルール、C#自動化コード、VBAコード、PowerShell起動ラッパー、画面PDF、返答形式と自動取込プロトコル。

**「標準」「コード修正だけ」のようなプリセットはありません。** 用途を推測して勝手に選ぶこともしません。C# と VBA は一方だけ・両方・どちらも無しがすべて選べ、**「その組合せは使わないはず」を理由に灰色になる項目はありません。** ある項目を触ったことを理由に別の項目が動くこともありません。［すべて選択］［すべて解除］はその場限りの手間省きで、あとから勝手に効き直したりしません。**エディターでいま見ている言語、AIへ渡すコードの選択、ビルドの対象は、互いに独立した3つの状態です。** 言語を切り替えてもビルドしても、チェックは1つも動きません。

［資料を作って依頼文をコピー］は、**押すたびに、いまの選択といまのコードから作り直します。** 前回の添付や前回のコードを「できている」ことにはしません。**1回のコピー**でテキスト1個をクリップボードへ置きます。**1回貼れば終わりです。分割はありません。**

依頼文に入るのは、あなたの依頼内容と、**実際に書き出した添付を読む指示**と、返却形式と、request id だけです。**コードも操作ログも台帳も依頼文には入りません。** それらは `ai/` の中の添付に入っていて、依頼文はそれを読ませます。**「必ず2ファイル」「コードは第10章」のような固定の文言はありません** ― 章番号は残った区分に1から振り直され、依頼文はそのとき実際に書かれた見出しと番号を読み取って書きます。コピーの前に、名指しした添付が実際に書けているか確かめ、無ければコピーせずどれが無いかを言います。

**全部のチェックを外すこともできます。** そのときは添付なしの依頼文だけができ、依頼文にも「添付はありません」と書きます。**存在しないファイルを読めとは書きません。** 画面PDFを外せば PDF は作られず、前回の PDF が添付フォルダに残ることもありません。返答形式を外せば、依頼文は自動取込できるとは書かず、返ってきたものを自動適用できるかのようにも扱いません（手で確かめて反映する道は残ります）。

選択の結果は**生成を止めない警告**として出ます ― コードを1つも選んでいない、画面PDFがOFF、返答形式がOFF、録画の説明の大半を外している。警告は何が欠けるかを言うだけで、**チェックを勝手に直しません。** それでも生成はできます。

作ったあとは、**含めた区分・C#モジュール数・VBAモジュール数・PDFページ数・各ファイルの bytes・適用された上限や圧縮や省略**が同じ場所に出ます。画面に出る数は実ファイルと一致します。

［添付フォルダをエクスプローラーで開く］がその添付のある場所を開きます。中にあるのは、最後に作った依頼のぶんだけです。

［返答を貼り付けから取り込む］は **1回の貼り付け**で受けます。返答は request id 付きの区切り行で包まれているので、**古い返答や別の依頼への返答は取り込まれません**。1回の貼り付けから複数の PowerShell ファイル・VBA モジュールを識別して仕分けます。長い返答は1ファイルずつ番号付きで受け取り、欠落・順序・重複・総数不一致・内容衝突を検査して再結合します。

**取り込んでも即座には上書きしません。** 中央のエディターがそのまま差分表示に切り替わり、**窓の幅と高さを丸ごと使って**変更の全体を見せます。［反映］を押して初めて置き換わり、［拒否］なら画面のコードは1文字も変わりません。狭い欄に数行ずつ出して判断させることはしません ― 見えていない変更に同意はできないからです。録画から生成した初期版にはいつでも戻せます。取り込めなかったときは理由を具体的に出します。黙って一部だけ適用したり、失敗を成功に見せたりしません。

## 画面

画面は **ひとつ** です。作業の状態はセッション1つで、それを見る形が2つあるだけです。ホーム・案内・記録閲覧・コード編集といった別々の画面と、その間の行き来はありません。

### フル表示（起動時）

上に固定のツールバー、その下に3つのペインが並びます。

| 場所 | 中身 |
|---|---|
| 上部バー | 録画 / スナップ / 録画設定 / **現在のセッション選択** / セッションのフォルダ / テーマ / 設定 / 表示切替 |
| 左（約20%） | モジュール。上端の PowerShell / VBA 切替で言語を選び、渡す1本の下に C# 本体とビルド時に書かれる PowerShell ラッパーを階層で出します |
| 中央（約50%） | コードエディター。検証・ビルド・実行・生成物の起動はこの下にあります |
| 右（約30%） | 「ワークフロー」と「AIに相談」のタブ。既定はワークフロー |

上部バーには **窓全体にかかる操作だけ** を置いています。再生はワークフローの隣、ビルドはコードの隣にあります。どの操作が何に効くのかを、置き場所で示すためです。

左右のペインはそれぞれ畳めます。畳むと戻すための細い帯が残り、**空いた幅は中央だけが取ります** ― 反対側のペインは1ピクセルも動きません。境界はドラッグで動かせ、動かした幅は畳んで開いても戻ります。**3つのペインの幅は常に窓の幅にちょうど収まります。** 窓を最小幅より狭くできない範囲まで縮めても、はみ出して右端が画面外へ出ることはなく、各ペインの最小幅が比例して譲られます。操作の並びが増えて1行に入らなくなったときは、行が折り返って2行になります ― 押せない場所へ追い出しません。

中央ペイン右上の全画面アイコンは、左右のペインに加えて**上部バーと状態行も畳み、窓をエディターだけにします**。戻すのは同じ場所のアイコンか `Escape` です。

**過去の記録は上部のセッション選択で切り替えます。** 選ぶと3つのペインすべてがその記録に変わります。別の「記録を見る」画面はありません。

**起動時には何も選ばれていません。** 前回のセッションを勝手に開くことはしません ― 開いた人は新しく始めに来たのであって、昨日終わった仕事を見に来たのではないからです。過去の記録に戻る道は今までどおりセッション選択1つだけで、そのための別のボタンはありません。

まだ何も記録していないときは、左に「まだコードはありません」、中央に「コードはまだ生成されていません。録画またはスナップ後に表示されます」と出ます。

### 最小表示

録画している間、この窓は録画したいアプリの邪魔になります。最小表示は同じセッションを**縦長の細い一列**に組み直した形です ― 録画は下へ伸びていくものなので、それに合う形は横に長いバーではなく縦の列で、細ければ録画したいアプリの**横に並べて置けます**。

持つのは **録画 / スナップ / 録画設定 / 現在のセッション / 再生 / 再生速度 / 現在のワークフロー / フル表示への復帰** です。それぞれが見出しの付いた区画に入っていて、手順は枠の中の一覧として、**窓を高くした分だけ長く**なります。手順一覧は畳めて、畳むと窓は残りの高さちょうどに縮みます。

**フルと最小を切り替えても、窓の位置は変わりません。** 左上の角はそのままで、画面から出るときだけ内側へ寄せます（以前は画面中央へ戻していたので、録画したいアプリの横に置いた窓が2回押すと真ん中へ行きました）。大きさは瞬間移動ではなく**短いアニメーション**で変わります。

**フルと最小の切り替えで、セッションも選んでいるモジュールも編集中の内容も失いません。** 録画を始めても表示形態は勝手に変わりません。選んだ形は `runtime/settings/view.txt` に残り、次に開いたときも同じ形で開きます。

### 録画中のパネル

録画中は画面上端に小さなパネルが出て、前面のウィンドウを赤い枠で囲みます。パネルにあるのは「● 録画中 mm:ss」と［停止］［一時停止］**だけ** です。ポインタの下の情報を出すかどうかは録画設定にある1つのスイッチで決めます（同じ設定を2か所に置くと、片方で切っても もう片方が「オン」と言い続けるためです）。

［一時停止］の間は何も見ていません。**見ていなかった区間はセッションの限界に必ず残ります。** 静かな2分と、見ていなかった2分は別物だからです。

パネルの大きさは中身から決まり、中身が変わるたびに測り直します。再生中に「再生中 12/40」と桁が増えても、一時停止ボタンが縁で切れることはありません。

### 共通の決まり

- 意味が一般に通じる操作は **SVG のアイコン** で描きます（設定＝歯車、テーマ＝月／太陽、全画面＝標準の全画面アイコン）。絵文字は使いません。字形も色も大きさも機械ごとに変わるためです。**描かれた操作には必ず名前と説明が付いていて**、ポインタを置けば言葉で出ます。
- オン／オフの設定は **スイッチ** です。ボタンにして「ポインタ情報: オン」と書くと、それが現在の状態なのか押した結果なのかを読み手に考えさせます。
- テーマ切替と設定は、どの表示形態でも同じ場所にあります。
- **押すまで結果が分からない語は置きません。**
- AI の返答は貼り付けても即座には反映されません。中央のエディターが差分表示に切り替わり、幅と高さを丸ごと使って全部を見せてから、［反映］か［拒否］を選ばせます。

`report.html` の並びは変わっていません。**結論 → 数値 → 警告 → 次の一手 → 詳細**。折り畳みは1段だけです。まとめの数値は割合の帯としても描かれ、詳細テーブルの絞り込み欄には何を絞り込むのかが書いてあります。

**どの窓もデスクトップの作業領域に収まります。** 画面より高いウィンドウは大きいウィンドウではなく、下の帯がタスクバーの裏にあるウィンドウです。

## AI へ渡すのは、選んだものだけ

セッションが終わると `runtime/sessions/<id>/out/` に次が書かれます。

| file | 用途 |
|---|---|
| `report.html` | 人が読む自己完結レポート。検索・絞込み・折畳みのできる表形式 |
| `ai/session.md` | AI へ渡すテキスト。**選んだ区分だけ**が、1から振り直した番号と目次つきで入ります |
| `ai/screens.pdf` | AI へ渡す画面。1画面1ページのラベル付きスクリーンショット。**画面PDFを選んだときだけ**書かれます |

**`ai/` の中身は、いま渡すものと常に一致します。** `session.json` も画像別添も増えません。前の依頼で書いたファイルが選択から外れたら、次に作るときに取り除きます ― 残っていれば添付されてしまうからです。だから「`ai/` フォルダの中身をそのまま AI チャットへ渡す」が完結した指示であり続けます。

コード編集画面から相談するときの依頼文は `runtime/sessions/<id>/code/request.md` に書かれます。**`ai/` には入れません。** 同じ理由です。

`screens.pdf` には明示的な容量予算があります。超えた場合は決められた手順で画像を縮小し、それでも収まらないときだけ画面を落とします。**縮小も省略も `session.md` と `report.html` に必ず書きます。**

## 記録するもの・しないもの

- **キーストリームは読みません。** ショートカットは Ctrl / Alt / Windows キーを押している間だけ、加えて Enter・Tab・Esc・F1〜F12 単独を、キー名として記録します。修飾なしの英数字キーは **キー名を記録しません**。「打鍵が起きた」ことだけを知るために状態を読みますが、どのキーだったかはどこにも残りません。**記号・句読点キーは監視表に無く、一度も問い合わせません。**
- **入力した文字はキー入力から取りません。** 入力先の要素から読み戻します。
- **秘密欄の値は絶対に保存しません。** `IsPassword`、パスワード用ウィンドウスタイル、`password` / `PIN` / `token` などの名前で判定し、値はどの出力にも残りません。再生時は操作者に入力を求めて止まります。
- **画像でも秘密欄は黒塗りします。** 黒塗りの有無は画面ごとに明記します。
- **録画・スナップ・再生の間、クリップボードは読みません。** 前面でないアプリの内容は取りません。画面録画もしません。クリップボードを読むのは1箇所だけ ― コード編集画面で［返答を貼り付けから取り込む］を押したときです。押さなければ読みません。

値の記録方針は詳細設定で「文字を記録（既定・再生に必要）」と「文字数だけ記録」を切り替えられます。どちらを選んだかは全出力に書かれます。

## 安全側の既定

- 再生は実アプリを操作するため、**詳細設定で明示的に許可するまで実行できません。**
- 他のウィンドウに覆われた座標へは操作を出しません。
- 操作の直前に、その座標が対象プロセスのものか確認します。違えば何も送りません。
- パスワード要素への `setValue` / `keys` は常に拒否します。要素の素性が確認できなかった場合の書込みも拒否します。
- 状態を変える操作を、方式比較のために連続実行しません。経路が繰り上がるのは、前の経路が `notSupported`（＝何もしていない）を返した場合と `focus` が失敗した場合だけです。
- パターンを持っていても前後の変化を観測できなければ `unknown` として記録し、`success` へ丸めません。
- `Shift+F12` で全停止し、実アプリ操作の許可も解除します。

## 動作要件

- Windows（UI Automation / MSAA / Win32 が利用できること）
- Windows PowerShell **5.1**（`launch.vbs` は明示的に 5.1 を起動します）
- .NET Framework（`Add-Type` による C# 5.0 相当のコンパイルが可能なこと）

## 起動

```
launch.vbs                                      # 非表示の Windows PowerShell 5.1 で起動する
powershell -File app-studio.ps1 -CompileOnly    # コンパイルだけ確認する
powershell -File app-studio.ps1 -Headless       # 診断だけ書き出す
```

UI Automation の取得は `app-studio-worker.ps1` の子プロセスへ隔離されます。対象アプリが応答しなくなっても本体は生き残ります。

記録は `runtime/sessions/<sessionId>/` へ逐次追記されます。**明示的な保存操作はありません。** 強制終了しても書けた分は残ります。`runtime/` は端末固有の状態なのでバージョン管理から除外しています。

## テスト

```
powershell -File tests/build-fixtures.ps1      # fixture アプリを tests/.build/ へ作る
powershell -File tests/run-all.ps1             # 全テストを走らせる
powershell -File tests/wp-s/build-wp-s.ps1     # WP-S ハーネスを作る
powershell -File tests/wp-s/run-wp-s.ps1       # WP-S 計測を artifacts/ へ出す
```

`run-all.ps1` は**実マウス・実キーボードを出すテストを既定では実行しません**。それらは `APPSTUDIO_ALLOW_REAL_INPUT=1` を立てたときだけ走り、立てない場合は黙って飛ばさず `SKIP` 行を出します。**誰かが使っている端末では立てないでください。**

fixture が緑でも受け入れの根拠にはなりません。実際のアプリの実画面で確認してください。

## 既知の限界

- 対象が内部のアクセシビリティ階層を公開しない場合、取得できる粒度はウィンドウ単位まで落ちます。その場合も無反応にはせず、「このアプリは構造を公開していない」「画像だけが唯一の記述である」ことを report と session.md の両方に明記します。
- 名前も AutomationId も階層 path も ctrlId も持たない要素は、**再生できません。** 位置と兄弟中の順番は記録して見せますが、それらを住所として使うことはありません。
- 画像・UIA・`PrintWindow`・`SendInput` の品質は、対象の実装・権限・デスクトップの状態に依存します。
- OCR は対象外です。低レベル入力フックは**ポインタにだけ**使います（`WH_MOUSE_LL`）。wheel には読める状態が無く、drag の解放点も double click も polling では存在しないためです。**キーボードは hook しません。** フックを張れない環境では左ボタンの押下だけを見る縮退動作になり、その事実と失われる情報をセッションの限界に明記します。

その他の制約は `docs/SPEC.md` の「既知の限界」にまとめています。

## リポジトリの注意

`.gitattributes` は `* -text` を指定しています。`core.autocrlf=true` の環境でチェックアウト時に全ファイルの改行が書き換わるのを防ぐためです。**この指定を外さないでください。**
